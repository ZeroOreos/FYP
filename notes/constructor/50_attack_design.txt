# Constructor Attack Design

Attack shortlist
- Face swap:
- `simswap`
- `reface`
- `faceshifter`
- Reenactment:
- `fomm`
- Adversarial impersonation:
- `advfacegan`
- Morphing:
- `dim`
- `mordiff`
- optional `mipgan`

Working benchmark target
- `simswap`
- `reface`
- `advfacegan`
- `fomm`
- `dim`
- `mordiff`
- optional: `mipgan`

Priority interpretation
- Core current-phase benchmark families are face swap, reenactment, and adversarial impersonation because they align most directly with the current implemented verification-attack question
- Morphing should remain represented, but it is supporting breadth for the broader deepfake benchmark rather than the sole center of the FYP
- `mordiff` is enough to keep morphing in scope for the current phase even if `dim` or `mipgan` remain partial
- `mipgan` should be treated as optional enrichment only; faithful native `dim` and `mipgan` are useful additions, but they are not blockers for the current phase of the FYP

Method labeling rule
- In docs and writing, label each backend as one of:
- faithful upstream
- patched upstream
- approximation / best attempt
- blocked / unverified

Writing rule
- In the thesis narrative, describe the current attack suite as benchmark construction for the prevention / detection and local-deployment evaluation that was always part of the intended FYP scope
- Avoid implying that every shortlisted backend must be fully operational before the FYP has a defensible core result

Compatibility target
- Attack backends should move toward both CUDA-compatible and Apple/CoreML-friendly execution where practical
- CPU-only patches are acceptable for verification and debugging, but not the ideal final state
