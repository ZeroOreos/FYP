# Constructor Data And Metadata

Dataset form
- Root form: `Dataset/<dataset>/<transform_chain>_<base_root>`
- Clean roots are canonical references such as `main`, `train`, `val`
- Recognition variants preserve identity folders, filenames, and relative paths
- Preprocessing and protection variants change pixels only
- Attack variants mimic the same folder form and contain manipulated faces

Naming
- Base root is the rightmost suffix token
- Transform chain sits to the left of the base root and uses `__`
- Chain order is newest-leftmost
- Adding a modifier or attack prepends a new token

Attack dataset rule
- Folder name is the claimed identity / victim identity
- Output file name must retain the original source file name exactly
- Metadata should record only what is not safely inferable from structure and naming

Attack metadata
- Defined by `Attack/metadata.py`
- Written by `Attack/materialize.py`
- Dataset-level fields should capture input root, output root, base dataset, base root, variant name, attack method, generator, seed, pair input, counts, and path rules
- Per-sample records should be omitted unless they explain failed or ambiguous cases

Reproducibility
- Attack generators must be deterministic for the same config, pair, and seed
- Effective parameters must be written to metadata
- Do not silently rename or silently drop samples
- If output and metadata already exist, compare request metadata before reuse
