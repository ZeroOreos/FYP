# Model Adaptations Log

Purpose
- Keep an exact per-model record of what was changed locally to make an upstream model run in this repo.
- Use this for methods writing, reproducibility notes, and honesty about fidelity.
- Append new entries. Do not delete old ones; mark them superseded if needed.
- Keep track of accelerator compatibility status too, especially CUDA and Apple/CoreML paths for attack backends.

- Local files patched:
- `Modifiers/attack/reface/wrapper.py`
- `external/REFace_upstream/ldm/modules/encoders/modules.py`
- `external/REFace_upstream/scripts/inference_swap_selected.py`
- `external/REFace_upstream/ldm/models/diffusion/ddim.py`
- `external/REFace_upstream/ldm/models/diffusion/plms.py`
- `external/REFace_upstream/ldm/models/diffusion/ddpm.py`
- `external/REFace_upstream/ldm/data/video_swap_dataset.py`
- `external/REFace_upstream/pretrained/face_parsing/face_parsing_demo.py`
- `external/REFace_upstream/pretrained/face_parsing/model.py`
- Local adaptations:
- added a new FYP wrapper at `Modifiers/attack/reface/`
- registered `reface` in `Utility/runtime.py`
- wrapper now sets local cache env vars for Matplotlib, Hugging Face, and Torch so upstream downloads resolve in stable repo-owned locations instead of `tmp/`
- wrapper exports `REFACE_CLIP_MODEL_DIR` and offline HF flags so CLIP loads from a local cache instead of calling Hugging Face at runtime
- fixed wrapper output resolution so it no longer falls back to copied source images when upstream produces no result
- patched `ldm/modules/encoders/modules.py` so CLIP tokenizer/model loading can resolve from the local CLIP model directory
- patched `scripts/inference_swap_selected.py` for CPU-safe execution:
- model load avoids unconditional `.cuda()`
- reference image tensor uses `float32` on CPU
- autocast only activates on CUDA
- DataLoader uses `num_workers=0` and `pin_memory=False` on CPU
- patched `ldm/models/diffusion/ddim.py` and `ldm/models/diffusion/plms.py` to register buffers on the actual model device instead of assuming CUDA
- patched `ldm/models/diffusion/ddpm.py` so ArcFace-related checkpoint loads use `map_location=torch.device('cpu')` when CUDA is unavailable
- removed dead `clip` and `bezier` imports from `ldm/data/video_swap_dataset.py`
- patched face parsing code in `pretrained/face_parsing/face_parsing_demo.py` and `pretrained/face_parsing/model.py`:
- CPU-aware checkpoint deserialization
- CPU-safe mean/std and bicubic downsampling path
- parser defaults to CPU when CUDA is unavailable
- seeded all required local caches and weights that upstream tried to download at runtime:
- OpenAI CLIP `openai/clip-vit-large-patch14`
- PyTorch `resnet18-5c106cde.pth`
- LPIPS AlexNet weights
- HardNet checkpoint
- installed `dlib-bin` instead of source-building `dlib`, because source build failed on this machine’s CMake path
- Fidelity note:
- best-effort wrapper around the official REFace repo; verified working on CPU with offline cache seeding and targeted compatibility patches
- Remaining caveats:
- not a byte-faithful original CUDA environment
- verification used `--ddim-steps 1` for a practical smoke test, not a full-quality benchmark setting

Current durable-cache check
- As of 2026-03-27, REFace was the only verified model with required runtime assets still living under `tmp/`.
- SimSwap and FOMM already keep their required weights in stable repo locations.
- As of 2026-03-27, the attack-model side is also the main area that still needs broader CUDA/CoreML compatibility vetting.
