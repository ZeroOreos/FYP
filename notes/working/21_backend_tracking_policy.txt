# Backend Tracking Policy

Canonical tracked backend references
- `Backends/manifest.json` is the canonical registry for backend layout and active local roots.
- `notes/working/20_backend_adaptations.txt` is the detailed provenance and adaptation log.
- Local FYP-facing code stays tracked under `Modifiers/attack/`, `Models/protection/`, and `Models/<recognizer>/`.
- Backend bootstrap and asset helpers stay tracked under `scripts/`.

Source-tree policy
- `Backends/sources/**` defaults to local-only and should not be tracked wholesale in git.
- Keep upstream provenance in notes and manifest rather than vendoring entire upstream trees into the git history.
- Track only key upstream files: README/license/provenance files plus the exact upstream entrypoints referenced by the local wrappers.
- If a backend needs another specific upstream file called out for reproducibility, add that single path intentionally instead of tracking the whole tree.

Operational note
- The repo may still use local source snapshots under `Backends/sources/` at runtime, but those trees are treated as environment material rather than tracked source-of-record.
