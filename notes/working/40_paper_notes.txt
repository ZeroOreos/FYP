# Paper Notes

WIFS direction
- Target venue framing: information forensics and security, not a pure attack-benchmark venue
- Keep the paper centered on a forensics / security claim:
- manipulated-face attacks can mislead verification systems
- layered defenses differ in what they prevent, what they detect, and what remains practical to deploy locally
- attack benchmarking is necessary infrastructure, but it should not be the whole headline contribution
- current honest fit status:
- on-topic for biometrics, deep learning for forensics, and privacy / anonymity
- not yet paper-centered enough if the evaluated story stops at attack success rate alone
- strongest narrative path is a layered-defense study using a shared manipulated-probe benchmark and explicit deployment constraints

Current working shortlist
- Family-complete target set is `simswap`, `reface`, `advfacegan`, `fomm`, `dim`, and `mordiff`; treat `mipgan` as optional enrichment rather than an active build priority
- Keep `fomm` analytically separate as reenactment rather than mixing it directly into swap or morph conclusions
- Layered defense evaluation with locally deployable models was always part of the intended FYP plan; the current repo state reflects attack-benchmark construction being implemented first
- paper-scope rule: prefer a smaller verified set that supports one sharp claim over a larger partially faithful set

Recognition-model interpretation
- Current recognizer set is `InsightFace`, `FaceNet`, `AdaFace`, and `MagFace`
- `FaceNet`: classic baseline; useful as an older, simpler verifier reference point
- `InsightFace`: strongest current anchor baseline; effectively an ArcFace-family modern verifier in the current repo
- `AdaFace`: integrated quality-adaptive modern baseline; checkpoint-backed local generation is now wired and smoke-tested
- `MagFace`: integrated quality-aware modern baseline; checkpoint-backed local generation is now wired and smoke-tested
- practical recognizer roadmap: keep the current four-model set unless a later paper need justifies replacing one rather than growing the zoo further
- avoid growing a large recognizer zoo; the point is to reduce over-dependence on one verifier family, not to make recognizers the whole thesis
- `FaceNet` may make aggregate evaluation look weaker because it is an older and usually weaker verifier than `InsightFace`; that is analytically useful, but it should not control the whole paper narrative
- reporting rule: do not collapse `FaceNet` and `InsightFace` into one vague pooled headline; show recognizer-specific results first, then summarize cross-recognizer trends
- interpretation rule: treat `FaceNet` as a legacy breadth baseline, `InsightFace` as the ArcFace-family modern anchor, and `AdaFace` / `MagFace` as quality-aware modern cross-checks rather than separate thesis centers
- paper-writing rule: recognizers are measurement instruments and robustness cross-checks, not the main novelty axis

Licensing and source summary
- `simswap`: official `neuralchen/SimSwap` upstream is vendored locally; license is CC BY-NC 4.0, so treat it as non-commercial / research-use only
- `fomm`: official `AliaksandrSiarohin/first-order-model` upstream is vendored locally; license is MIT
- `faceshifter`: vendored local tree is `maum-ai/faceshifter`, which is an unofficial AEI-focused implementation rather than the canonical official release; license is BSD 3-Clause, but trustworthy pretrained weights were not established
- `reface`: official `Sanoojan/REFace` upstream is vendored locally; license is MIT; this is the strongest current replacement for the retired `faceshifter` slot
- `advfacegan`: preserved upstream tree is present locally and the wrapper is verified, but the vendored tree does not currently include a clear top-level license file; treat source provenance as present but license status as needing tighter confirmation
- `mordiff`: official upstream morphing script is vendored locally; the README states CC BY-NC-SA 4.0 and explicitly restricts use to research purposes rather than product development or competitions
- `dim`: native source import is from `zblasingame/Greedy-DiM`; the vendored repo license is MIT, but the runnable morphing code is encrypted and gated behind the CITeR release-form process
- `mipgan`: local tree currently contains the official NTNU public portal snapshot rather than the runnable native package; public users are instructed to sign the license form and request the password for the code-and-model archive
- `diffae`: vendored dependency used by `mordiff`; license is MIT

Working interpretation
- strongest permissive-license provenance in the active set is currently `fomm`, `reface`, and `diffae`
- strongest research-only / non-commercial provenance in the active set is currently `simswap` and `mordiff`
- most important remaining source / licensing ambiguity to clean up is `advfacegan`
- most important gated-release methods are `dim` and `mipgan`
