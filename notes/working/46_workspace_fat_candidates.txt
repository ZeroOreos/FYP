Models/
- `Models/FaceNet/` and `Models/InsightFace/` are both unusually large for code trees.
- Likely cause:
  - local support / vendored runtime material under model directories, not just scripts
- Needs a second pass before deletion:
  - these are active model trees, so anything here should be audited file-by-file first

Backends/workdirs/
- This is the most likely next major fat source after backend assets.
- Current evidence:
  - many backend methods have dedicated workdirs
  - workdirs likely contain local virtualenvs, package caches, matplotlib caches, and run outputs
- Observed subtrees:
  - `Backends/workdirs/attack/{advfacegan,dim,fomm,mipgan,mordiff,reface,simswap}`
  - `Backends/workdirs/protection/{deepprivacy2,faceshield,facial_attributes_obfuscation,falco,fawkes,m2f2_det,unidefense}`
  - `Backends/workdirs/recognition/{adaface,facenet,insightface,magface}`
- Safe-to-investigate classes inside workdirs:
  - virtual environments: `venv`, `.venv`, `venv_mps`, `venv_cpu`, `venv_cuda`
  - `__pycache__/`
  - `.cache/`
  - `matplotlib/`
  - run-output dirs like `outputs/`, `results/`, `samples/`, `logs/`, `stage1-det/`
- Confirmed minor cache examples:
  - `Backends/workdirs/protection/deepprivacy2/outputs/` is empty
  - matplotlib caches under workdirs are tiny (`~144K` scale)
- Conclusion:
  - the real likely savings here are virtualenvs, not matplotlib caches
